# SRBX選択時の停止対策

## 確認した記録

2026-10-26 14:43起動のPrism Launcherコンソールで、Minecraftの終了コード143を確認。latest.log/debug.logにJava例外や通常のクラッシュレポートはなく、終了を発生させた直接の原因は特定できていない。

選択画面のプレビューはVehicleScriptRenderers.getから約1,000万文字へ展開されるSRBXスクリプトを描画スレッドで同期コンパイルしていた。実パックを用いた計測で、この準備・コンパイルに28,110msかかることを確認した。この間UIが応答しなくなる経路を修正した。

## 変更

- 読み込み・include展開・コンパイルだけを、単一の専用デーモンワーカーへ移した。
- 選択画面と車両レンダラーはコンパイルの完了を待たずに戻る。読み込み中は既存の静的モデルを使い、画面に読み込み中と表示する。
- JavaScriptのトップレベル評価、renderer.init、ゲーム・GL操作は、完了後に従来の呼び出しスレッドで実行する。
- 同じモデルへの毎フレームの要求は同じFutureを共有し、コンパイルを重複させない。失敗時はモデル名とスクリプト名をログに残す。

## 検証

Async selection regressions: 9件成功。要求がブロックしないこと、重複要求の共有、ワーカーがパックスクリプトのトップレベルを実行しないこと、評価スレッドの維持、構文エラー、実SRBXのinitとプレビュー描画を確認した。

実SRBX計測:

| 処理 | 時間 |
| --- | ---: |
| 選択側の要求 | 0ms（1ms未満） |
| バックグラウンド準備・コンパイル | 28,110ms |
| 完了後のトップレベル評価 | 388ms |
| init | 37ms |
| 初回プレビュー両パス | 9ms |

既存スクリプト、設定、モデル、レール、インベントリの回帰検査成功。GPUのシェーダー4本、カメラFBO5件、半透明の色・深度40件、サンプラー4組合せ、PNG/GPU全1,048,576画素のRGBA一致も確認。JAR生成成功。

通常のMinecraftウィンドウでユーザーの操作を再現した検査ではない。終了コード143の直接原因を証明した修正とも扱わない。今回確実に直したのは、選択時に描画スレッドで長時間のコンパイルを実行する停止経路。SRBXの初回準備時間そのものは残るが、その間もUIを処理できる。

ユーザーのmodsフォルダ、起動設定、セーブデータは変更していない。
