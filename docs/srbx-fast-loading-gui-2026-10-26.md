# SRBXの読み込み高速化・GUI互換修正（NeoForge 1.21.1）

2026-10-26。検査対象は手元のSuperRailBuilderX-v1.0.0.zip。Fabricは対象外。

## 確認した原因

Prismの最新ログの15:39:05に、render_rail_mover.jsから呼ぶGL11.glGetErrorが関数として存在せず、描画スクリプトが停止した記録がある。従来のnull車両プレビュー検査は、実際のGUI関数へ進まないため、この不足を検出できていなかった。

読み込みでは、生成された互換ターゲットのincludeが再帰的に本文へ展開されていた。builder1では約984万文字に達し、前回の実測で準備・コンパイルに28,110msかかっていた。

## 実装

- LegacyExecutionIncludesで、生成されたRTMXのガード付きターゲットグラフを共有ソース表とdirect evalへ変換する。未選択ターゲットの本文を巨大なエントリへ埋め込まない。includeの反復実行と呼び出し先の関数スコープを保持する。
- 一般のパック、strictやlexical宣言を含むパック、小さいグラフは従来の文字列展開を継続する。一般スクリプトの宣言巻き上げをdirect evalで変更しない。循環・欠落includeは例外で報告する。元のPackScriptSource.prepareの公開仕様は変更しない。
- 描画とCarServerScriptsの準備・コンパイルを共通の単一ワーカーへ移す。トップレベル評価・初期化・ゲーム操作は従来の呼び出しスレッドで実行する。CarEntityは処理中のnullを最終結果として保存せず、完了後に再取得する。
- GL11のエラー取得、行列の保存・復元、投影、テクスチャ行列、状態問い合わせ、色マスク、GL13のテクスチャユニット、GL14の独立ブレンドを互換層へ接続する。削除された固定機能GLをcore profileへ直接呼び出さない。
- GUIの投影切り替え前にバッファをflushし、ワールドの投影やモデルビューがGUIへ混入しないようにする。正常終了・異常終了でGPU状態を復元する。GUIのアトラスUVにはテクスチャ行列を適用する。
- Minecraft互換クラスに画面寸法、GUI倍率、Unicode指定、フォント幅・文字描画を追加し、文字をコマンドとして記録・再生する。
- コンパイル時間、エントリ文字数、共有モジュール数、従来の展開文字数をログに出力する。

## 実測

同じ実SRBX builder1、初回の読み込み。実行環境やJVMの状態によって変動する。

| 処理 | 今回 |
| --- | ---: |
| 選択要求 | 0ms（1ms未満） |
| 準備・コンパイル | 2,772ms |
| 完了後のトップレベル評価 | 957ms |
| init | 27ms |
| 初回プレビュー両パス | 8ms |

初回に使用可能になるまで合計約3.8秒。前回の準備・コンパイル28,110msから、準備・コンパイルは約90%短縮。builder1のエントリは107,684文字＋共有56モジュール。単なる読み込み中表示の追加ではなく、実際にコンパイルする重複本文を減らしている。
