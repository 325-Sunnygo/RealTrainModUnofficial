# 本家比較画像に基づく道床・レール種類の修正

対象はNeoForge。本家比較画像では木製レールの下に砂利の道床がある一方、1.21側は草地が露出している。ユーザーの保存データを読み取り専用で比較したところ、1.21側の1067mm_WoodはProperty.BlockName=minecraft:air、本家側の1067mm_Woodはminecraft:gravelだった。E131のMc.mqoとparts.pngは両インスタンスで同一のSHA-256だった。

これは道床の設定差を確認したものであり、画像の影割れの全原因を断定するものではない。実行中のゲーム操作、ワールド起動、保存データ書き換えは行っていない。

## 修正した違い

- RailItemの敷設済みレールへの適用で、アイテムの道床を無視して設置済みのblock/meta/heightを引き継いでいた。本家ItemRail同様、持っているアイテムの完全なプロパティを適用する。
- 同じモデル名の場合に置き換えを拒否していた処理を削除。同じ1067mm_Woodでも空気から砂利へ変更できる。
- BlockMarker.propertyForが選択済みの道床をモデルのdefaultBallast一覧に限定していた。本家ItemRail.setModelNameと同様、モデル変更と道床選択を独立させた。明示的な空気はそのまま保持する。
- 既定プロパティのモデル名を空文字から本家の1067mm_Woodへ修正。未選択時の砂利・高さ1/16を維持する。
- 種類別アイテムにblockIdだけでなく、Property NBTとしてmetaとheightも保持。同じブロックIDの別メタ・別高さが潰れないようにする。
- 本家の路面電車用carpet/meta7が1.21のレジストリで見つからず空気になる問題を修正。旧ブロック名と色メタをGRAY_CARPETなどの現行ブロックへ変換し、本家NBT読み込み時にも適用する。MODの名前空間は維持する。
- 道床のモデルがmetaを無視していたため、解決済みのBlockStateを使用する。旧grassは草ブロックを意味するため、短い草への誤変換も修正。
- 本家RenderBlockLargeRailは四隅の高さをそのまま使う。RTMUが高さを0〜1に切り詰めていた処理を削除し、勾配・カントの形を保持する。非有限値のみ既定高さへ置き換える。
- 本家の道床は固定の面方向陰影で描く。追加されていたAOを外し、面方向の陰影を残す。

## 種類・標準素材

本家に同梱された24種類のModelRail_*.jsonを同一バイト列で取り込んだ。依存するMQO、JS、JSのinclude、レール画像・ボタン画像を追い、計70ファイルを同一にした。Cableのボタン画像指定にも相違があったため本家へ揃えた。追加パックやRTMU追加定義は削除していない。

SHA-256一覧は `docs/verification/kaizpatchx-rail-assets.json`。

## 検証

- 回帰検査314件成功（うち道床・レールプロパティ39件）。全24定義の一致、全種登録、木製レールの砂利、雪の高さ、明示的な空気の保持、NBT、メタ・高さの保持、カーペット色変換、MOD名前空間、カント高さを検査。
- scriptPreflight成功。ただしゲームの外では解決できないバインディングの警告が残るため、全動作の保証とは扱わない。
- NeoForge JARビルド成功。ユーザーのmodsフォルダにはコピーしていない。

## 既存線の更新

すでに保存された道床=空気の線路は勝手に砂利へ変えない。明示的な空気と過去の誤設定は区別できないためである。

砂利の1067mm_Woodアイテムを持ち、スニークしながら既存線を右クリックすると、同じレール名でも道床込みで置き換えられる。普通の右クリックは本家どおり重ねレールなので、置換にはスニークが必要。

実ゲームでの影の改善は未確認。KaizPatchXのチャンク自動分割など、今回対象外の差も残るため、レール処理全体の完全互換達成とは判定していない。
